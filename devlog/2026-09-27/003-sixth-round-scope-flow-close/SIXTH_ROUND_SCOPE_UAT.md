本修订补充并优先约束前序第六轮合同。前序已完成的人工月绑定、支持部卡片、历史参考层、多文件组表、批量人员确认和轻量 defer 改动必须保留。只扩展角色/范围、无底薪人员语义、页面职责与主导航；不重做工资核心算法。

## 冻结范围

不重做：AA / AC / AD / AE / AF；Roster 的排课事实来源；续费、退费、批注、模板、导出、启动器；AG / AL / AS。不得因缺值把字段补 0。兼职工资三路径退出主流程；按课时人员的金额由组长提交资料提供，系统只读取、不计算兼职工资。

## 正式流程

1. **角色选择**：进入工资核算先选择 DOS / 教学管理者或学科组长。两种角色共用同一套工资计算与 Run 持久化，只改变核算范围和页面责任。
2. **材料准备**：一个“工资资料”模块内提供“导入本月工资资料”（本月权威、最高优先）和“导入历史工资参考”（只作参考）。清楚显示本月权威是否存在、历史参考是否存在及当前生效状态。
3. **教师名单与归属**：确认当前角色的处理范围、组别、历史组籍与小学科归属。
4. **待处理问题**：全部需要确认、选择、接受、暂缓、决定采用哪个来源的表单集中在此处。
5. **工资预览与导出**：只查看结果和导出，不放大批处理表单。删除含义近似的“核对结果和导出”独立终点，只保留一个最终预览/导出页。

所有页面固定展示当前位置和步骤；提供上一步、保存并继续、下一步。处理具体问题期间固定停留在“待处理问题”，显示待处理 / 已处理 / 暂缓计数、问题路径、返回列表与“保存并处理下一项”。解决一个问题后，新问题追加到队列，不把用户跳回材料页或其它不相关页。

## DOS / 教学管理者范围

- 范围为当前 ACTIVE 人工月内排课表的全部教师，排课仍是本月教学部 Roster 权威源。
- 负责全教学部漏人检查、支持部本月权威工资资料、多学科组提交资料、全教学部历史参考覆盖率、统一核算和导出。
- 缺本月资料时显示覆盖/来源状态；只对实际属于全教学部范围且需要处理的业务事项产生待处理问题。

## 学科组长范围

组长不承担全教学部完整性责任。组长处理范围仅为以下身份集合的并集，再按已确认/候选科组归属收敛到本人所选科组：历史排课属于本组的人、历史工资参考属于本组的人、本组当前提交资料中的人。

未进入本组范围的其它教师：不得提示缺支持部资料、历史工资、G～L、用工性质或归属；不得生成逐人待处理异常；不得因全教学部 Roster 有 51 人而要求组长核完整教学部。

组长选择科组后，只对该组范围内人员做教师名单确认、资料覆盖和工资核算。历史组籍只作为候选，不足以确认的教师由用户一次勾选确认后持久化，后续月份默认沿用。

**实现边界（保护已确认的 Roster 契约）**：当前人工月全体排课名单始终是 canonical payroll Roster，继续写入原有 `schedule_roster_snapshot`；不能把它覆盖成组长名单。DOS 的处理范围等于 canonical Roster。组长的处理范围等于“历史组籍 / 历史工资参考组籍 / 本组当前提交资料”确认成员的并集，再与本月 canonical Roster 求交集。组外教师保留在事实 Roster，但不得进入组长的工资缺资料、用工、M 或续费待处理；组表里不在本月排课的教师只作为来源范围提示，不可新增本月工资行。已有历史课程快照并非完整教师名册，不能单独据此声称历史人员全集。

## 组别与小学科确认

历史工资参考导入时，必须先选择科组：数学、理化、语文、英语、其他。系统按排课主学科给出自动归组候选；地理、生物、政治等小学科教师单独列出，并允许用户勾选实际归属。身份/组别不明确只影响该人员归属，不扩大为全教学部待处理问题。

组籍确认以稳定 teacher_id 为主键，可跨月复用；科组例外可编辑。明确的少数例外不要求对整组每人重复保存。

## 工资资料优先级与历史参考

材料页统一显示一个“工资资料”模块：

- **导入本月工资资料**：本月正式权威来源，优先级最高。
- **导入历史工资参考**：只作为身份、归组、星级候选、历史用工、G～L 与长期政策线索；不默认成为本月工资。

历史工资禁止默认复制：上月续费、退费、月度激励、考勤罚款、课时费和 AV。G～L 默认标记“历史参考”，只有负责人明确确认后才可本月暂用。确认是 Run/当月级决定并保留来源哈希与操作者；不得延伸成以后月份的正式工资 authority。若本月支持部资料确认存在，优先支持部，不允许历史参考覆盖。

历史工资参考导入时需先选所属科组；主学科教师作为自动归组候选，小学科教师单独列出并经负责人勾选确认。该名单作为可追溯组籍证据，但历史表中的教师若不在本月排课 Roster，不会成为本月工资行。

## 无底薪 / 按课时人员

- 有本月正式底薪资料：按有底薪人员处理。
- 本组人员明确确认“无底薪、按课时”：标记为 `HOURLY_SUBMISSION_ONLY`（或等价明确状态）；系统不计算兼职工资，由本组提交表给出应支付结果，系统仅读取、核验来源和状态。
- 仅仅没有工资资料：保持 `UNKNOWN / SOURCE_MISSING`，不推断为兼职/按课时。
- “明确无底薪、按课时”必须与既有 `PART_TIME` 用工事实分开保存；不得触发旧兼职课次费率或兼职工资三路径。
- 组长范围之外的教师缺少本组资料，不得因此成为按课时或兼职。
- 原公司兼职费率、自动算价、手填兼职金额/单价/暂留白不进入本轮主流程；旧存量数据不得悄然转换为“已确认无底薪”。

## 待处理问题与暂缓

所有人需要参与的决定都集中到待处理问题页；材料页只做上传、替换、移除、查看来源，名单页只做范围/归属。暂缓只保存状态，不触发核算、不跳页。只有用户明确点击“开始核算/重新核算”才读取材料、计算 2,385 条排课并生成预览。

## 性能 / Snapshot

上传文件首次解析后持久化来源哈希、教师与字段快照。查看、确认、计数、科组覆盖、问题队列更新优先使用 snapshot；轻量确认不重新读全部 Excel、不重算全月排课、不生成完整预览。快照必须和来源 hash 绑定；hash 变化时标记失效，要求只重新解析受影响文件。只有明确的全量核算动作执行完整计算。

## 验收与安全

- DOS fixture：全教学部排课范围、全组覆盖、遗漏检测、全量本月工资来源。
- 组长 fixture：全教学部教师中只有目标组交集进入名单/待处理；其它组教师不出现于缺资料问题。历史 roster、历史工资名单、当前提交表并集可重现且身份不模糊。
- 明确无底薪可由本组表提供并只读进入结果；缺资料仍为 UNKNOWN；组外教师绝不由缺资料推断为按课时。
- 历史资料组别选择、小学科教师勾选后 reload/新 Run 复用。
- 资料入口单模块显示权威来源优先级；旧历史业务字段不污染当前 Run。
- 待处理列表状态计数和处理位置稳定；完成/暂缓后仍在待处理页，问题列表可返回并继续下一项。
- 导航唯一终点为“工资预览与导出”；每一步的返回/继续能正确持久化。
- defer 不调用 check；轻操作不重读全部源；源 hash 变化仅失效该源 snapshot。
- 不修改真实生产 SQLite。真实浏览器操作未执行不得标 PASS；使用隔离 DB/脱敏 fixtures 完成自动化。

### 实现结果

- Run 新增独立 `operator_role` / `selected_group`；旧 Run 和旧 service caller 缺省按 DOS 兼容，正式 UI 新建 Run 必须显式选择 DOS 或学科组长，组长必须选择科组。核算方式 `AUDIT / GENERATE` 与角色完全分离。
- canonical Roster 仍是完整人工月排课快照，`roster_authority` 不被重写。新增 `processing_scope`：DOS 为完整 Roster；组长为已确认长期组籍、历史参考成员与本组当前确认提交资料的并集，再与当月 Roster 求交集。检查、用工/工资基础覆盖与生成对象按处理范围过滤；组外人员不会被判缺资料。
- 历史工资资料导入前选择科组。主学科可由当前排课/来源科组给出候选，小学科和无法确定人员另列勾选。确认的组籍成员写入现有长期教师组籍表，并保留来源 SHA、行号、确认人/时间。历史工资参考现在可作为多份资料集合参与覆盖率和组长 scope；G～L 仍需单独确认才可本月采用。
- 工资基础状态与 `FULL_TIME / PART_TIME` 用工事实分离：`HAS_BASE_SALARY`、`HOURLY_SUBMISSION_ONLY`、`SOURCE_UNKNOWN`。缺资料不会被推断为兼职。正式 UI 创建的新 Run 不再启用兼职计价：明确按课时人员从本组提交表读取 AA/AC/AD/AE/AF/AV 现值，`PART_TIME` 金额不计算；旧 Run/service compatibility mode 保持旧值可读，不被静默迁移。
- Run 导航改为四步：准备材料 → 教师名单与归属 → 待处理问题 → 工资预览与导出。工资资料统一在一个入口模块；支持部、历史组籍、小学科确认、工资基础、组表确认及人工月冲突卡进入待处理问题。待处理页显示位置和计数；保存决定后留在原页，可返回列表或继续下一项。defer 和历史年级确认不触发全量核算。只有明确点击“开始核算/重新核算”读取全部源并运行 Core。
- 支持部、历史工资、学科组的解析候选均持久化到当前 Run。学科组确认复用解析行快照；本月支持部确认复用预览快照；历史工资组籍/成员候选可在重新打开 Run 后继续确认。来源 hash/size/mtime 变化时，核算前 fail-closed；轻量打开/状态检查优先用 stat 和 normalized snapshot，显式核算时完整校验 hash。
