## 原始观察整理

### 1. 基本工资应支持整表导入

当前逐格录入基本工资不可用，也不符合真实工作方式。用户已有基本工资表，应通过一份历史工资数据表导入教师基本工资。可用来源包括支持部门提供的标准工资表，或上个月教学部的工资表；两类表的结构相同，界面统一提供“历史工资数据”导入入口即可。没有匹配到的教师再逐项提示补充，不应要求全体教师逐格录入。

### 2. 核对问题必须能进入实际处理

工资公示异常和“需确认”状态目前对用户不够可解释。点击“处理”应直接到对应确认表单，并显示当前问题、需要做的决定和保存反馈。

本次 UAT 中，用户完成了义务课时默认规则及一位匿名教师的例外确认，设置了默认 30 小时、例外 0 小时和原因“带组且没有星级”，随后保存默认规则、例外和确认。用户认可这段流程。

默认 30 小时是惯例规则，不应标为“本月例外”。例外应与默认规则分开、可追溯。此项已有确认的业务输入，施工时不得改动星级加成或个人政策算法。

### 3. 所有操作都要有即时反馈

点击后无反应不可接受。异步操作开始时，按钮应显示处理中并禁用，或出现清楚的进度提示；完成后显示成功，失败时显示可操作的错误信息。UAT 特别观察到“暂不录入，先生成工资表”点击后没有可见反馈。

### 4. 工资预览需要收短备注

预览页备注过长，影响快速检查。保留必要状态与异常原因，详细说明应折叠或按需查看；不要在每一行重复大段提示。

### 5. 模板缺失提示应给出直接入口

生成工资表时出现“尚未设置工资模板，请先到基础资料中设置一次”，但当时没有明确跳转入口，也找不到导航。缺模板时应提供直接跳转/继续设置按钮，设置保存后能返回原流程继续生成。

用户提供的真实公司模板可以只有表头行；模板录入时不得要求提交一份带历史工资数据的旧工资表。模板列、星级来源等尚未验证的地方只做清楚说明，不得改变星级加成或个人政策。

### 6. 工资周期异常需要核实真实覆盖范围

用户已导入 2026-08-01 至 2026-08-30 的课表和续费数据，但界面仍提示排课周期异常。必须对照本 Run 实际导入材料的日期范围与核算周期定位校验原因。不能仅凭文件名或硬编码的月初/月末判断异常。

### 7. 续费材料应出现在当前 Run 的核对结果中

用户表示续费已经导入，预期在本 Run 查看续费核对结果；页面却显示“查看其他项目”，随后续费内容未按预期出现。需要检查材料类别识别、问题聚合和页面导航状态，确认已导入续费数据关联到正确月份、教师和当前 Run。

### 8. 星级规则的查看入口和来源需说清楚

用户不清楚当前教师星级从哪里确定、42/43 等显示值代表什么、如何查看依据。当前阶段只要求让来源、当前值、规则入口和待确认状态清楚可见；不要改动星级加成或个人政策。

## 验收合同

1. 一张兼容结构的历史工资数据表可批量导入基本工资；只有未匹配项需要补录。
2. 默认义务课时和教师例外可从核对问题直接进入、保存、确认并看到状态反馈；惯例规则不标成月度例外。
3. 异步按钮都有处理中/成功/失败的可见状态，并能阻止重复点击。
4. 预览备注简明，详细原因按需展开。
5. 缺模板时有明确的一步设置入口；保存后可返回并继续生成。
6. 核算周期提示与真实导入数据日期一致，不误报完整覆盖的 8 月周期。
7. 当前 Run 已导入的续费可进入续费核对视图，类别、月份、教师匹配状态可解释。
8. 星级值及其数据来源可发现；星级加成和个人政策算法保持不变。
9. 不改写原始工资表或原始课表；所有更正均留在本地 Run 的可追溯数据中。
10. 真实 UI 回归通过，且定向自动化回归通过；任何未解决项继续标为 OPEN，不伪称 UAT PASS。
