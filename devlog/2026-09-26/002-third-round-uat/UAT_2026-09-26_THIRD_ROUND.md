# 2026-09-26 Payroll 第三轮真实 UAT

## 目标

在现有 2026-08 Run 和已提交修复上，完成兼职工资三种处理方式、续费确认到导出、退费批注、支持部批注和班课依据批注的真实闭环。不得重做人工月、AA/AC/AD/AE/AF 算法或模板版式。

## 固定边界

- 兼职长期身份与本月付款决定分开保存；不得使用代码内姓名/单价默认值。
- 公司标准只可来自带来源、生效期及版本的权威费率资料。知识库/Skill 未给出正式兼职费率时，自动标准必须保持待权威来源；不得把历史示例价当作标准。
- 手动填写支持本月总额或单价；明确暂缓时工资值保持空白，不得变成 0。
- 续费须按当前 Run 的月份预览并由用户明确确认，确认后快照持久化，页面、刷新、重开和最终 Excel 使用相同 canonical result。
- 退费 AN 与 AN 单元格批注必须从同一份已批准 Run 结果生成。
- 支持部单元格批注必须先进入 snapshot，再按字段绑定到最终工资单元格；不得复制源工作簿对象或旧工资值。
- 班课批注只能说明当前 AC/Core 实际计算依据，不得另造业务公式。
- 任何待确认或缺失数据不得静默补零。
- 真实数据库写入前必须已有可校验备份；原始源文件只读。

## UAT 项目

| ID | 验收项 | 通过条件 |
|---|---|---|
| PT-01 | 兼职选项可用 | 当前兼职教师可选择公司标准、手动、暂时留白；页面保存有反馈。 |
| PT-02 | 兼职决定持久化 | 保存后刷新及重新打开 Run 仍显示方法、状态、来源和审核信息。 |
| PT-03 | 兼职结果语义 | 公司标准仅用有效权威版本；手动总额/单价进入 canonical result；DEFERRED 保持空白而不是 0。 |
| RN-01 | 续费按钮闭环 | 导入/识别、月度预览、确认反馈、刷新、重新打开、AK/AV 与最终导出一致。 |
| RF-01 | 退费 AN 与批注 | 同一批准来源的教师、学生/业务类型、金额明细和来源写入 AN 对应单元格 comment；重新打开 XLSX 验证。 |
| SD-01 | 支持部批注链 | 统计真实源批注；抽样源单元格→snapshot→最终单元格，字段、教师、文字可追溯。 |
| CL-01 | 班课解释批注 | 至少三条有 AC 结果的真实教师行有简明、可读的计算依据批注；不得复制大量原始排课。 |
| X-01 | 模板保真 | 输出工作表结构、样式、公式位置、冻结窗格、行高列宽、批注不偏移；最终文件可重开。 |
| X-02 | 页面与导出一致 | 预览和导出读取同一 canonical payroll result。 |
| G-01 | 自动化回归 | 定向测试通过后只运行一次 `sh tools/run_tests.sh`；记录 GitHub CI 实际结果。 |

## 必须区分的证据层级

- 自动化测试通过不等于真实浏览器 UAT 通过。
- 浏览器页面出现批注数据不等于 Excel 批注已回填。
- 只有重新打开最终 XLSX 并检查实际单元格 comment 后，RF-01/SD-01/CL-01 才能 PASS。
- 当前真实兼职费率来源不存在时，PT-03 的公司标准分支为 OPEN；不得据此伪造整体 PASS。
- 真实用户尚未指定三位兼职分别使用哪种方式，也未提供手动工资数额时，不得替其确认；相应真实数据 UAT 保持 OPEN。

## 真实范围与保护

- Run: 当前 2026-08 真实 Run；所有修改必须保留 actor/time/source，并在既有 SQLite 备份后执行。
- 真实工资、教师、学生、文件路径和截图不得进入公开测试夹具或 GitHub 日志。
- 不修改 AA / AC / AD / AE / AF 的已确认核心规则；AC 仅添加证据说明，不更改金额。
- 不修改当前认可模板布局。
