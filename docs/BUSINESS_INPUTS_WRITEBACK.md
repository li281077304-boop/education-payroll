# 业务输入与批注回填

## 数据流

业务输入先作为结构化记录保存，经过人工审核后才可绑定月度 Run。绑定并不自动改变工资结果；它只提供可追溯的审核依据。

教师提交、续费最终结果和退费最终结果共用 `BusinessInputRecord`。每条记录保留月份、教师、来源、文件 hash、行号、原始 payload、审核人、审核结论和关联 Run。

## 权限与审核

教师访问码只保存 hash。教师端只能创建、查看自己的事项和保存自己的草稿；不能访问管理员 API、其他教师记录、工资结果或规则。教师提交默认 `SUBMITTED`，不是 `APPROVED`。

上游续费/退费结果导入后为 `NEEDS_REVIEW`。同月导入新版本会将旧版本标记为 `SUPERSEDED`，不删除历史。当前没有可靠续费奖励规则时，系统只归档和展示结果，不计算奖金。

## 批注候选与回填

候选批注来自已审核退费结果，或已确认的结构化班课处理。候选先为 `PROPOSED`，管理员预览并明确确认后才为 `APPROVED`。回填只输出新的工作簿，绝不覆盖原工资表。

已有批注默认 `APPEND`；也支持保留原批注或经明确确认替换。输出后系统重新打开新文件，验证目标批注存在，并检查原公式未被意外改变。

## Resolution 边界

当前分支不实现或复制未提交的 `SOURCE_DATA_CORRECTION` / `APPROVED_PAYROLL_OVERRIDE` 半成品。它只提供一个严格接口：只有状态已确认的结构化 resolution 才可生成确定性班课批注；`DEFERRED` 或仅“可能原因”不能自动生成最终批注。

## 失效与留档

Run 绑定业务输入时记录输入 id 与 source hash。上游结果被 supersede 或来源文件变化后，Run 进入既有 STALE/重新确认流程。工资表或已绑定业务结果变化时，尚未写入的批注候选变为 `NEEDS_RECONFIRMATION`。
