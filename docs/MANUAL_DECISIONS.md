# 人工裁决目录

本目录只记录“需要人决定的事项类型”，不记录真实教师、学生、金额或原始业务明细。

| 场景 | 为什么不能只靠当前程序 | 当前实际处理方式 |
|---|---|---|
| 排课导出版本选择 | 同月有多个导出；在读班可能升级，结课班名可能不变 | 以用户确认的中段导出版为权威，逐条/按匹配规则复核；旧版脚本结果不自动覆盖最终表 |
| 未识别年级 | 班级名不含标准年级，或需要学生查表；学生查表本身不能提交仓库 | 程序列出未知项；人工补充/确认后再继续 |
| 衔接班定级 | “小升初”等班名代表当前在读年级，不是字面目标年级 | 按当前 Skill 的映射人工复核异常项 |
| 班课代课折算 | 系统排课行与实际价值不一致，没有标准 M | 用户决定折算次数；静态写入 AC 并写拆分批注 |
| 实到为 0 但已上课 | 可能是请假、特殊状态或不计课，不同情况处理不同 | 先用学员/时间定位，再由人决定是否计入 |
| 班课批注与系统不符 | 批注是教师填报口径，系统是排课口径；差异不一定意味着数值必改 | 逐人按年级×实到统计对照；先重写批注，数值修改需确认 |
| 星级与工资表 F 列不一致 | F 列可能过时或填错；AD 档位边界也会影响反推 | 参考上月已核星级、人工口头确认或覆盖 CSV；不自动覆盖 |
| AE/AF 人工特例 | 管理/底薪行、TRMT、历史人工值不一定走通用公式 | 用脚本列出异常，人工判断是否为合法特例 |
| 续费表版本冲突 | 新版可能少人或改名单，不能把缺行自动当成 0 | 对比旧版/新版，同月缺失列疑点，用户确认采用哪个版本 |
| 续费消息归属 | 消息可能混有客服、班主任、外校老师、别名和错别字 | v3 先按首名判断二校，再按名单、别名和任课人数分摊；解析失败人工回看 |
| 续费消息课时格式异常 | 自然语言中的“课时/次/ks/领航”组合不固定 | 脚本列出解析失败；人工核对原消息和续费表 |
| 退费月份缺失 | 无法自动判定历史政策区间或绩效归属 | 依据现有业务口径人工决定；不能用空月份猜测 |
| 退费扣款对象不一致 | 学科教师列和实际扣款教师列可能不同 | 以退费表扣款教师列为归属；异常或补扣由人确认 |
| 兼职单价 | 每月可能变化，不应直接套上月 | 逐人确认本月单价，再按节数×单价写 AF |
| 教师名单差集 | 排课老师、薪资表老师可能属于不同组或无课 | 先列差集；确认跨组、全职无课、兼职无课和身份变化 |
| 管理岗位总学员数/考核值 | 部分指标由统计表展示，脚本只打印，规则文件不完整 | 人工从统计/考核表取数，按当前绩效说明写入并复核 |
| 外部链接更新 | WPS/Excel 是否更新链接会影响填报数据页 | 打开源薪资表和核对表，确认更新链接；预览面板不能作为唯一判断依据 |
| 最终通过 | 当前没有全链路自动门禁 | 人工按 Skill 十四逐项输出通过或异常名单 |
