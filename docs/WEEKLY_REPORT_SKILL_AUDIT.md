## 2. 核心脚本

## 3. 输入文件

- `auto_fill.py` → `数学组周报_第N周_自动生成.xlsx`

## 5. 读取哪些 Sheet / 单元格

| 来源 | 读取 |

| 底稿「源数据」 | 教师姓名行 + 「科  组」行 |

| 底稿「满班率」 | 含「数学」的行 |
| 底稿「教师」「组课时生产」 | 科组汇总行 / 第 N 周行 |

## 6. 写入哪些 Sheet / 单元格

- **源数据**：列 2–19（一对一 E/H/S、KS、次数、停课、周均；班课 E/H/S、班级、KS、次数、停课；单科、总课时当量、总次数）
- **学生**：第 5 行，列 0–16（周次、总单科、一对一拆分、停课、新增、结课、班课拆分、开班数）
- **满班率**：数学行，列 1–20（分班型学生数与班级数、容量、满班率）
- **教师**：科组行，列 2–10
- **组课时生产**：第 5 行，只填 `A, C, H, I, L, M, N, O, Q, R, S`（其余为公式列，保持不动）

## 8. 如何复制上周数据

```python
rb = xlrd.open_workbook(base_file, formatting_info=False)

```

## 9. 哪些指标自动读取

一对一 E/H/S、一对一 KS/次数、班课 E/H/S、班课 KS/次数、班级数、总单科、总课时当量、周均（v1h ÷ 学生数）、教师数、满班率相关。

## 10. 哪些指标依赖人工

- **学生数**：来自 WPS（权威），不是算出来的
- **停课**：沿用上周（WPS 停课不可靠）
- **新增 / 结课**：WPS 学员变动表 + 人工排除换班
- **退费**：独立退费文件
- **退费列**：明确要求留空

## 11. 学生数现在到底怎么处理

> **学生数以 WPS 汇总表为主（Primary），NEVER compute from schedule。**

SKILL.md 原文："Student counts (1v1/班课) | WPS源数据 teacher rows | Primary — NEVER compute from schedule"。
并且明确承认："学生数经常对不上，属于可解释差异"，例如教师离职学员清零、班课学生数填错、小初高拆分的人工口径调整。
**结论：系统推算值只能是参考，最终人工填报值才是权威值。**

## 12–14. 一对一 / 班课 / 总学生数

- 一对一学生数：`v1_e + v1_h + v1_s`（WPS）
- 班课学生数：`b_e + b_h + b_s`（WPS），班级数 `bk_c`（WPS，排课可能含已取消班级）
- 总学生数 `all_stu = (v1_e+v1_h+v1_s) + (b_e+b_h+b_s)`
- 两个口径必须分清：教师 Sheet 单科总数 = 1v1 生 + **班课班级数**；学生 Sheet 单科数 = 1v1 生 + **班课生**

## 15–16. 一对一周平均 / 平均课次

- 一对一周均 = `v1h ÷ (v1_e+v1_h+v1_s)`；**< 2.0 且 ≥ 3 个学生 = 预警**
- 班课平均课次 = `bkt ÷ bk_c`
- 总课时当量 **C = v1h + bkh/3**（不是 v1h+bkh，因为 bkh 已经 ×3）

## 17. 有没有历史修正逻辑

有，且很实在：
- `EXCLUDE`（钱瑞、宋涛）不计入正式教师数
- `SPECIAL`（王星、宋涛）特殊授课，从 F/G 公式里减掉
- **`实到 = 0` 必须先过滤**（2026-09-10 用户定案，公司级口径）—— 不过滤会系统性多算
  （真实证据：9/10 服务贡献奖，理化组 9 人不过滤 2522 节、过滤后 2490 节，**多算 32 节**）
- "一对多/一对二" 不得误判为一对一：`is_1v1 = '一对一' in fmt and '一对多' not in fmt`

- 教师名单、EXCLUDE、SPECIAL 写死在脚本顶部

## 19. 有没有 WPS / Excel 兼容问题

**有，而且当前是硬阻塞：**

| 依赖 | 本机状态 |
|---|---|
| `xlrd` | 2.0.2（可用，但 2.x 已不支持 xlsx） |
| `xlutils` | **缺失** |
| `xlwt` | **缺失** |
| `openpyxl` | 3.1.5 |

→ `auto_weekly.py` **目前在这台机器上跑不起来**（`from xlutils.copy import copy` 会 ImportError）。

其它坑（SKILL.md 已记录）：
- `xlwt.Formula()` 不可用，必须写**计算后的值**
- 不要把 xlrd 的 XF 索引复制到 xlwt（会导致文件损坏）
- openpyxl 打不开某些 `.xls`（内容实际是 OOXML），脚本里的规避方式是先复制到临时目录再打开

## 20–22. 复用判断

### REUSE_AS_IS

- 业务口径：一对一 3 课时/次、班课按实到、**实到=0 必须过滤**
- 交叉验证流程：WPS vs 排课逐教师比对，差异超阈值必须列出明细
- 自恰性校验：满班率总学生 = 学生 Sheet 班课生；满班率班数 = 生产 M 值
- 只写指定列、保留公式列（组课时生产只填 A/C/H/I/L/M/N/O/Q/R/S）
- "差异必须给出原因"，不能只报有差异
- 生成后校验清单（Post-Generation Verification）

### REUSE_WITH_ADAPTER

- **回填机制本身**（复制上周 → 写值 → 另存），但需要换依赖：
  `xlutils/xlwt` 当前缺失且老旧，建议改为 openpyxl 方案，或先补齐依赖并固定 `xlrd<2`
- `auto_weekly.py` 的解析逻辑：列号改**按标签扫描**（子 Skill 已提此要求）
- 排课解析：班型识别、日期区间过滤（可与 payroll 的语义映射引擎共用思路）
- 教师名单：改为读云端 `rosters.md`，不写死在脚本里

### BUSINESS_RULE_ONLY

（这些是知识，不该写死成代码常量）

- 学生数 = 人工/WPS 权威值，**系统不能自动算出绝对真值**
- 停课沿用上周
- 新增/结课来自 WPS 学员变动表，需人工排除换班
- 退费留空 / 来自独立退费文件
- 一对一周均 < 2.0 且 ≥ 3 学生 = 预警
- 总课时当量 = v1h + bkh/3
- 单科数的两个口径（班级数 vs 学生数）
- 满班率的经验比例（14/44、89/195 等，属人工口径，应可配置）
- 教师编制与兼职/特殊授课划分（权威在 rosters.md）

### DEPRECATE

- `templates/auto_fill.py` 的从零生成路线（不保留老 Excel 的格式与公式，与"写回老 Excel"方向相反）
- 写死的行号、列号、输出文件名
- 写死的教师名单 / EXCLUDE / SPECIAL
- 周次 → 日期映射写死（应由实际日期推断）
- 满班率魔数写死

## 未来形态（只写结论，本轮不开发）

```
上周已确认周报
  → 自动复制基础数据（保留格式与公式）
  → 从可信来源读取能可靠读取的数据（排课 → 课时生产类）
  → 把「变化」展示给人（WPS 值 vs 排课推算值）
  → 人工确认 / 修改
  → 最终填报值成为本周权威值
  → 写回原来的老 Excel（另存新文件，不动原文件）
```

**"最终填报值"优先级最高。** 系统可以保存：

- `previous_value`（上周值）
- `suggested_value`（系统建议）
- `final_value`（**人工最终值，权威**）
- `source`（来源）
- `manual_adjustment`（人工加减）
- `note`（差异原因）

系统建议值只能参考，**不能推翻最终填报值**。本轮不实现这个数据模型，只在此说明。
