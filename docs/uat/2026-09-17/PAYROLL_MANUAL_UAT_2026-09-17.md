# Payroll 真实 UAT — 2026-09-17

> 来源：2026-09-17 用户本人对当前 Payroll 工程进行的真实手工 UAT。
> 目标：把真实工资流程闭合为“待处理问题 → 补资料/确认例外 → 生成 → 预览 → 按公司原工资模板导出”。

## 总结

当前系统已经具备“发现问题、记录后台异常、返回独立错误编号”的基础，但 UI 操作链仍有明显断点。最严重的阻塞不是配色，而是：

1. 待处理页教师筛选框输入后失效；
2. “51 位教师”等聚合结果缺少显式可点击入口；
3. “无特殊情况”有入口，“有特殊情况”缺少同层入口；
4. 30 小时扣除确认点击后无处理中反馈，并发生后台失败；
5. 缺基本工资时，当前页没有明确的“现在上传 / 稍后上传 / 继续生成”下一步；
6. 工资预览信息密度过高，状态语义不统一；
7. 星级缺失目前疑似被默认二星，需要改成待确认；
8. 最终导出的“标准工资表”与公司真实工资模板不一致，这是本轮最严重的交付阻断项。

## UAT 中确认的正向点

- “51 位教师”这一聚合统计本身看起来有价值。
- “确认人”输入框当前可正常使用，可作为教师筛选输入体验的参考。
- 后台异常会生成独立错误编号；例如 `4ac7c59609da3256`。不同失败事件使用不同编号是合理的。
- AA/AC 等字段已经开始保留来源和确定性信息，方向正确，只需要降低展示噪音。

## 本轮关闭条件

- 待处理页能在本页完成补资料、暂缓、例外确认与下一步操作；
- 所有关键异步动作有 loading / success / failure；
- 教师筛选框不再“一字后失焦”；
- 缺星级不再默认二星冒充已确定；
- 工资预览可完整滚动，统一三色状态；
- **最终导出恢复为公司既有工资模板格式。**
