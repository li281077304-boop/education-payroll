# Development Principles

> education-payroll 长期开发原则。
>
> Worker、Ralph、External Chief 在开始重要任务前均应阅读本文件。

## 1. 产品第一

我们的目标不是：

pytest passed

而是：

真实用户可以稳定地完成真实业务。

当前首要闭环：

真实资料
→ 正确工资
→ 可核验 Excel

## 2. 真实 UAT > Synthetic Test

Synthetic tests 很重要，
但不能代替真实 Excel / WPS / 真实历史数据测试。

当 synthetic test 和真实 UAT 冲突时：

优先调查真实 UAT。

## 3. Golden 是答案册

Golden Baseline 是验证标准。

禁止：

- 修改 expected 迎合当前程序
- 把错误结果重新定义为正确
- 直接抄 Golden 教师工资作为生产计算

允许：

- 学习标准公式模式
- 学习模板结构
- 做 Value Diff
- 做 Formula Diff

## 4. 能读出来，不猜

如果真实文件、历史资料、公式、已有代码中已经有答案：

先读取。

优先级：

真实证据
>
已有规则
>
合理推断
>
询问用户

不能因为模型“觉得可能是这样”就创造业务规则。

## 5. 技术问题 AI 自己解决

以下通常不应 HUMAN_REQUIRED：

- bug
- test fail
- parser 问题
- Excel 读取问题
- UI 技术问题
- 重构
- 文件兼容
- 路径问题

只有真正的业务裁决才找用户。

## 6. 用户发现一次，机器以后守住

真人 UAT 发现的重要问题：

优先转成 regression test。

目标：

同一个坑不要让用户踩第二次。

## 7. 不为了 Loop 造需求

Loop 的目标不是：

跑满 token
跑满 8 小时
跑满 iteration

而是：

持续完成高价值工作。

明确 backlog 做完后：

进入 hardening / regression / real-file audit。

没有高价值工作时允许停止。

禁止自行创造外围业务功能。

## 8. 人和 AI 分工

用户负责：

- 真实使用
- 产品体验
- 业务判断
- 发现不合理

AI 负责：

- 整理 UAT
- 工程实现
- 自动测试
- 回归
- 审计
- 技术修复

原则：

用户勘探，
AI 施工。

## 9. 文件内容比手工 metadata 更有证据力

例如：

用户手工选择“9月”，
但上传课表实际全部属于“8月”。

系统不应该：

- 机械拒绝
- 偷偷改成 8 月

应该：

识别冲突
→ 给出证据
→ 用一次低成本确认帮助用户纠正。

## 10. 默认值应该帮助用户

可以自动确定的事情，不要求用户重复输入。

例如：

- 核算月份
- 输出路径
- 历史年级
- 权威星级
- 人员规则
- 模板

默认值必须可解释、可修改。

## 11. 输入错误要可恢复

成熟产品不能：

选错文件一次
→ 页面报废。

所有高风险输入必须支持：

- 删除
- 替换
- 重选
- 撤销
- 重置

## 12. 错误必须说人话

用户看到的是：

发生了什么
为什么
下一步怎么做

不是：

内部异常名
字段英文名
traceback
数据库术语

## 13. 来源必须可追溯

所有重要业务结果最好能够回答：

- 从哪个文件来的
- 哪个 Sheet
- 哪一行/区域
- 使用了什么规则
- 为什么采用这个结果

工资系统不能成为黑盒。

## 14. 不重复解析同一数据

同一个业务数据源：

只解析一次，
标准化后共享。

禁止：

工资模块读一遍周报，
考核模块再重新解释一次，
BI 第三次解释。

应逐步形成统一数据层。

## 15. 稳定优先

已确认正确的：

- 年级
- AA
- AC
- AD
- 星级
- AE
- AF
- Golden 公式
- Golden 数值

属于冻结回归资产。

新功能不能破坏它们。

## 16. 主流程优先于外围

优先级：

真实结果错误
>
流程阻塞
>
回归风险
>
可用性
>
健壮性
>
技术债
>
新功能

不允许因为外围功能更有趣而绕开工资主链问题。

## 17. UI 不暴露工程实现

普通用户不需要知道：

- Run ID
- Adapter
- YAML
- JSON
- Database
- internal field names
- Python path

这些可以存在于审计和开发层，
不属于普通业务 UI。

## 18. External Chief 独立审计

Chief 应尽可能直接检查：

- GitHub diff
- 代码
- 测试
- 架构
- regression

Machine Gate 负责检查本地私有真实数据。

不要要求 Worker 用长篇自述证明自己正确。

## 19. 隐私数据不进仓库

真实工资、学生、教师工资数据、私有 Excel：

不得为了方便 Chief 审计上传公开 GitHub。

仓库保留：

- schema
- 规则
- 脱敏 fixture
- hash
- 自动化代码
- 测试

真实数据留在受控本地环境。

## 20. 完成标准

一个功能完成，不等于：

代码写完。

至少应考虑：

- 主路径工作
- 错误路径可恢复
- 真实文件验证
- regression
- 用户能理解
- 结果可追溯

最终标准：

【真实用户现在能不能放心用它干活？】
