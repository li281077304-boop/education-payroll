# 开发原则

重要任务开始前请阅读：
`docs/UAT_BASELINE.md`、`docs/DEVELOPMENT_PRINCIPLES.md`、`docs/MANUAL_DECISIONS.md`

---

1. **真实 UAT > synthetic test**
   合成测试只能守住回归，不能证明产品可用。真实文件跑通才算完成。

2. **Golden 是答案册，不得改 expected 迎合程序**
   Golden 对不上，说明程序错了，不是答案错了。

3. **能从真实资料读取就不猜**
   读得到的用读的；读不到才进入人工确认，绝不静默编一个值。

4. **技术问题 AI 自己解决**
   环境、依赖、路径、编码、兼容性问题属于 AI 的活，不要丢给用户。

5. **真正业务未知才 HUMAN_REQUIRED**
   只有业务口径本身没定的时候才问人；口径已定的一律按口径执行。

6. **用户发现一次的问题尽量变 regression**
   真人踩到的坑必须转成自动化测试，不能靠"下次注意"。

7. **不为了跑满 loop 制造需求**
   没有真实问题就不硬找活干；宁可停在一个干净的 checkpoint。

8. **用户勘探，AI 施工**
   用户负责发现问题和定业务口径，AI 负责把口径落成可运行、可回归的代码。

9. **文件内容比手工 metadata 更有证据力**
   文件里的实际上课日期 > 人工填的月份 > 文件名。文件名只能做辅助。

10. **自动判断 + 低成本确认，不静默替用户决策**
    系统可以推断，但推断结果要让用户以一次点击成本确认或否决。

11. **错误输入必须可恢复**
    传错文件、选错月份、导出重名，都不能把用户带进死路，必须有回头路。

12. **错误提示说人话**
    说清缺什么、检测到了什么、下一步怎么做；不暴露工程概念。

13. **结果必须可追溯来源**
    每个数字都要能追到：哪个文件、哪张表、哪个单元格、哪条规则版本。

14. **同一数据统一解析，不重复解释**
    同一份文件只解析一次，多处复用；避免两套解析产生漂移。

15. **已确认正确的工资链稳定优先**
    已验证正确的 AA / AC / AD / AE / AF 链，优先保持稳定，改动要小步、可回退。

16. **主流程优先于外围功能**
    主流程没稳之前，不做周报、续费、退费审批、HR、CRM、BI 等外围。

17. **普通 UI 不暴露工程概念**
    界面上不出现 `Run` / `Adapter` / `YAML` / 绝对路径 / 内部模式名。

18. **Chief 尽量直接审 GitHub**
    交付以分支 + commit + PR 为准，避免来回搬运结论。

19. **私有工资、学生数据不得进入公开仓库**
    真实工资表、学生名单、排课原始数据只留在原始工作目录，不复制、不提交。

20. **"代码写完"不等于"产品完成"**
    写完只是开始；跑通真实 UAT、有回归守住、文档同步，才算完成。
