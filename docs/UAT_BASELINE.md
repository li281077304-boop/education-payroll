# UAT Baseline（真人验收基线）

本文件是**真人 UAT 的验收清单**，不是开发计划。

原则：**真实 UAT 优先于 synthetic test。**
每一条都必须能被真人用真实文件走一遍，并且尽量被机器自动守住。

状态标记：`PASS` = 已由真人/自动化确认｜`FIXED` = 本轮修复｜`TODO` = 未验证｜`BLOCKED` = 卡住

---

## 1. 真实 UAT 优先

- 验收点：任何工资链改动，先用真实排课表 + 真实工资表走一遍，再看单元测试。
- 状态：`PASS`（流程约定）
- 证据：本文档每一条都指向真实或等价脱敏文件。

## 2. 真实课表 → 正确工资 → 可核验 Excel

- 验收点：上传真实排课表后，系统算出的 AA / AC / AD / AE / AF 能被人工按公式复算，
  导出的 Excel 里能看到每一行的计算依据（年级系数 × 人数系数 × 系数 × 2）。
- 状态：`PASS`
- 证据：证据页「计算依据」列；`tests/test_core_calculation.py`

## 3. 20 日前默认核算上月

- 验收点：每月 1–19 日打开"开始核算"，默认月份 = 上一个自然月。
- 状态：`FIXED`（原先直接取当前月）
- 证据：`defaultPayrollPeriod(now)`；`tests/test_uat_night_regression.py`
- 用例：9/1 → 8月；9/19 → 8月；1/10 → 上一年 12月

## 4. 20 日及以后默认核算本月

- 验收点：每月 20 日起，默认月份 = 当前月。
- 状态：`FIXED`
- 用例：9/20 → 9月；9/30 → 9月

## 5. 文件实际日期与 UI 月份冲突的确认流程

- 验收点：UI 选 9 月、上传的课表主要属于 8 月时，**不报错终止、不静默改月份**，
  而是提示：
  > 检测到该课表主要属于 2026-08，当前核算月份为 2026-09。是否切换到 2026-08？
  并提供 `[切换到 8 月]` / `[仍按 9 月]`。
- 状态：`FIXED`
- 约束：切换后已上传文件不丢失、状态不重置、不要求重新上传。

## 6. 权威月份 / 人工月份交叉验证

- 验收点：月份判断优先级为
  1. 文件内**实际上课日期**
  2. 已有权威月份 / 人工月份资料
  3. 文件内部月份字段
  4. 文件名（仅辅助）

  文件名叫"8月排课.xlsx"但内容实际是 9 月时，必须以内容为准。
- 状态：`FIXED`

## 7. 日期覆盖完整性 warning

- 验收点：文件只覆盖 8/1–8/30 时，**不能直接判定错误**，而是给 WARNING：
  > 检测到本次课表覆盖 8月1日–8月30日，请确认是否已包含本月全部排课。
  并提供 `[继续核算]` / `[替换文件]`。
- 状态：`FIXED`
- 原则：这是 warning，不是默认 blocker。系统无法证明 8/31 本来就没课。

## 8. 历史年级自动加载

- 验收点：同一班级/学员的历史年级能被自动复用，不需要每月重新确认。
- 状态：`PASS`（年级决议 `schedule_grade_resolutions`）

## 9. 星级规则

- 验收点：星级来自独立星级权威资料，不是工资表里读出来的；
  缺星级时 AE 只能标"估算"或"待输入"，不得显示为已确认。
- 状态：`PASS`

## 10. 课时 = 0 不参与

- 验收点：实到人数为 0、未上课、已取消的记录不进入 AA / AC / AD。
- 状态：`PASS`

## 11. AA / AC / AD 回归

- 验收点：
  - AA 只算一对一；AC 只算非一对一；**AD = AA + AC**
  - 普通小班按实到人数系数（1人 0.8、2人 1.0、3人 1.2…）
  - 特殊班型（1对2 / 1对3）按 **(班型 × 实到人数)** 配置查表，不乘普通小班系数
- 状态：`PASS`

## 12. Golden Baseline

- 验收点：已有 Golden 数据集跑完 **Value Diff = NONE / Formula Diff = NONE**。
- 状态：`TODO`（需本地可访问 Golden 数据）
- 注意：Golden 是答案册，**不得改 expected 去迎合程序**。

## 13. Excel 真实公式

- 验收点：读取真实 Excel / WPS 文件时要能读到 cached value 与公式，
  外部链接未解析、缓存缺失都要如实报告，不能当 0。
- 状态：`PASS`

## 14. 同名导出自动递增

- 验收点：`工资表.xlsx` 已存在时自动输出 `工资表 (2).xlsx`，
  再存在则 `(3)`、`(4)`……**永不覆盖、不因重名失败、不要求用户手填路径**。
- 状态：`FIXED`（原先直接报"输出文件已存在，不能覆盖"）
- 用例：已有 (1)/(2)/(3) → 输出 (4)；文件名有空洞时选择不覆盖任何已有文件的安全名。

## 15. 上传文件查看 / 替换 / 删除 / 重置

- 验收点：已上传文件可查看、可替换、可删除、可重置，且不会把用户带进死路。
- 状态：`PASS`

## 16. 错误提示说人话

- 验收点：错误信息不出现 `Run` / `Adapter` / `YAML` / 绝对路径等工程概念；
  必须说明**缺什么、检测到了什么、下一步怎么办**。
- 状态：`PASS`

## 17. 真实 Excel / WPS 回归

- 验收点：真实 `.xls`（校管家导出）与 `.xlsx` 都能进入系统。
- 状态：`PASS`（含 `.xls` 后缀但内容为 OOXML 的真实导出）

## 18. UI 主流程

- 验收点：选择月份 → 上传排课 → （有工资表则核对 / 无则直接生成）→ 查看证据 → 导出。
- 状态：`PASS`

## 19. 禁止在主流程未稳定时乱扩功能

- 验收点：周报、续费、退费审批、HR、CRM、BI 等外围功能，
  在主流程未稳定前不得占用开发资源。
- 状态：`PASS`（原则约束）
