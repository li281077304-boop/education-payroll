# UAT Baseline

> 目的：把真实用户已经发现、确认过的问题和产品行为固化到仓库中，
> 作为后续 Ralph / Worker / Chief / Machine Gate 的长期验收基线。
>
> 本文件不保存真实工资、学生、教师薪酬等敏感数据。

## 1. 核心原则

- 真实 UAT 优先于继续扩功能。
- 当前第一目标始终是：
  真实课表 → 正确工资 → 可核验 Excel。
- 用户发现过一次且可以自动化的问题，应尽量转成永久 regression test。
- 问题优先级：
  BLOCKER / WRONG_RESULT > UX > LATER。

## 2. 核算月份

### 默认月份

- 每月 20 日之前：默认上一个自然月。
- 每月 20 日及以后：默认当前月。
- 用户始终可以手工切换。

例如：
2026-09-12 打开工资核算，
默认应为 2026-08。

### 上传课表月份核对

用户当前选择的月份不能成为机械阻断条件。

上传课表后，应根据实际上课日期判断课表主要属于哪个月份。

例如：

当前 UI = 2026-09
上传课表主要属于 = 2026-08

系统不应直接拒绝。

应该提示：

“检测到该课表主要属于 2026-08，
当前核算月份为 2026-09。
是否切换至 2026-08？”

操作：

- 切换到 8 月
- 仍按 9 月

不能静默修改月份。

### 人工月份 / 权威月份

如果存在人工月份表、权威月份资料或已确认月份规则，
必须与课表实际日期交叉核对。

不能只相信文件名。

需要结合：

- 实际上课日期
- 人工月份 / 权威月份
- 文件名
- 业务周期完整性

如果一个“8月课表”实际日期明显缺失、跨月或异常，
不能静默计算，应提示。

## 3. 基础资料

新建工资核算时，应自动加载已有权威资料：

- 历史年级证据
- 系统权威星级
- 上传资料星级
- 人员规则
- 已确认个人政策
- 工资模板

不能只有测试代码手工灌数据库以后才得到正确工资。

## 4. 工资核心链

必须持续守住：

原始课表
→ 年级
→ AA
→ AC
→ AD
→ 星级
→ AE
→ AF
→ 后续项目
→ 最终工资

已确认正确的数据不得因为后续开发静默回归。

课时=0 / 无有效上课事实的记录不得参与工资核算。

AD = AA + AC。

## 5. 星级

优先级固定：

1. 系统权威星级
2. 上传资料星级
3. 两者都没有 → 默认二星

发生冲突：

- 系统权威优先
- 保留冲突记录
- 不阻塞工资生成

## 6. 无发生项目

当月确实没有发生：

NO_EVENT → 0

理论上应有数据但来源没有加载：

MISSING_SOURCE

不能把 MISSING_SOURCE 伪装成 0。

## 7. Golden Baseline

Golden Baseline 是开发答案册，不是生产输入。

必须：

- 只读
- 不得为了让测试通过修改 Golden
- 不得直接抄教师最终工资结果
- 可以恢复标准公式结构和模板结构
- 持续检查 Golden Value Diff
- 持续检查 Golden Formula Diff

已确认 MATCH 的字段不能静默变化。

## 8. Excel

最终 Excel 应保持真实工资模板结构。

当前明确需要公式的项目：

- 一对一相关折算
- 总课时费
- 最终收课小时
- 后续折算课时

班课课时允许直接写值。

禁止用：

=68.77

这种伪公式冒充真实业务公式。

输出后必须重新打开并验证公式仍然存在。

## 9. 导出

普通用户不填写文件路径。

默认导出到用户可以找到的位置，例如：

Desktop/工资导出

同名时：

工资表.xlsx
工资表 (2).xlsx
工资表 (3).xlsx

不得：

- 静默覆盖
- 因文件已存在直接失败

如果 fallback 到其他位置，
UI 必须明确告诉用户文件在哪里，
最好支持“打开所在文件夹”。

## 10. 文件恢复

所有上传文件必须支持：

- 查看
- 替换
- 删除
- 重选
- 重置
- 返回

选错文件一次不能让整个流程死掉。

## 11. 错误提示

普通用户 UI 禁止直接显示：

missing normalized schedule columns

此类工程信息。

应该显示人话，例如：

《8月排课表.xlsx》无法作为排课表使用。

缺少：
- 任课老师
- 上课时间
- 教学形式

请重新选择正确文件。

## 12. 真实文件

不能只靠 synthetic fixture 宣称完成。

长期回归要覆盖：

- Excel
- WPS
- 公式
- cached value
- 合并单元格
- 旧模板
- 缺列
- 错文件
- 重复上传
- 文件替换

## 13. UI 主流程

主流程固定倾向于：

数据准备
→ 自动核算
→ 异常核对
→ 工资预览
→ 导出工资表

普通用户不需要理解：

- Run
- Adapter
- YAML
- 数据库
- 内部路径
- Excel 字母字段

## 14. 范围

工资主流程没有稳定以前，不要自行扩成：

- 完整续费系统
- 完整退费审批
- CRM
- HR
- BI 大屏
- AI 聊天
- 教师评分系统

## 15. UAT 节奏

推荐长期工作方式：

用户真实使用
→ 产生真实问题
→ 整理 UAT backlog
→ Ralph / Worker 施工
→ Machine Gate + Golden Gate + Chief
→ 用户测试新 checkpoint

用户负责体验和判断，
不要求用户自己写工程测试报告。
